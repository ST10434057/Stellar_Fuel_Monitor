# Part 2 AI Usage Write-Up (draft — under 500 words)

Generative AI was used during Part 2 as a development assistant while converting the existing Stellar Fuel Analytics prototype into a native Kotlin Android assessment copy. The group supplied the existing project source code, Part 1 Planning and Design document, assessment brief, system requirements and existing API architecture. AI assistance was then used to inspect the current Angular/Express structure, map existing web screens to Jetpack Compose equivalents, generate an initial Android project structure, and draft Kotlin data models that correspond to the existing REST API responses.

AI was also used to help structure Retrofit interfaces and repository classes, implement the first version of Firebase/Google Single Sign-On integration, create persistent Android DataStore settings, and translate the existing dashboard, fleet, trip, alert, report and utility workflows into native Compose screens. It also assisted with drafting unit-test scaffolding, GitHub Actions workflow configuration, migration documentation and developer setup instructions.

The existing Express/Node.js analytics code was not treated as AI-generated replacement logic. It was preserved from the group's Stellar project and tested in the conversion environment. The packaged backend test suite was executed and all nine tests passed. The existing REST API was also launched against its packaged data-cache fallback and representative endpoints were checked.

AI output must still be reviewed by the group before submission. In particular, the Android project must be opened in Android Studio, dependencies synchronised, Firebase credentials supplied by the group, and the application compiled and tested on a physical Android device. Group members remain responsible for understanding, testing, correcting and documenting the code they submit, and for citing external technical patterns or documentation where required by the assessment.
