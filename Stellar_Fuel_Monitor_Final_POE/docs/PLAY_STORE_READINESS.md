# Google Play Store Readiness

The repository contains the code-side release preparation. The final assessment still needs real release artefacts and screenshots generated by the team.

## Code-side readiness completed

- Stable application ID: `za.co.stellar.fuelmonitor`
- `versionCode = 3`, `versionName = 3.0-final-poe`
- Target/compile SDK 35
- Custom adaptive launcher icon resources
- Release minification and resource shrinking
- Release cleartext HTTP disabled
- Release signing reads credentials outside Git
- `.jks`, `.keystore`, `.aab` and release directory ignored
- GitHub tagged-release job builds signed APK + AAB from secrets
- Store listing draft
- Data-safety working document
- Privacy-policy working document
- Screenshot shot list

## GitHub Secrets required for tagged signed release

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`
- `STELLAR_API_BASE_URL`
- `FIREBASE_API_KEY`
- `FIREBASE_APP_ID`
- `FIREBASE_PROJECT_ID`
- `FIREBASE_MESSAGING_SENDER_ID`
- `GOOGLE_WEB_CLIENT_ID`
- `PLAY_STORE_PRIVACY_URL` (recommended)

The keystore should be Base64-encoded locally and added as a GitHub Actions secret. Never commit the keystore or the Base64 value.

## Final release procedure

1. Complete physical-device QA against the hosted HTTPS environment.
2. Create/confirm the final release signing key and back it up securely.
3. Add required GitHub Secrets.
4. Ensure the main branch is green.
5. Update `README.md` with the working final video URL.
6. Create an annotated tag:
   `git tag -a Final-POE -m "Final POE"`
7. Push the tag: `git push origin Final-POE`.
8. Confirm the **Signed Final POE release** GitHub Actions job succeeds.
9. Download the signed APK and AAB workflow artefact.
10. Install the signed APK on the physical test phone and repeat the smoke test.
11. Capture real screenshots per `play-store/screenshots/README.md`.
12. Confirm the privacy-policy URL is publicly reachable.
13. If actually uploading to Play Console, review current Play Console declarations and complete them truthfully using `play-store/data-safety.md` as a working draft.

## Do not claim ready until verified

A source repository cannot itself prove Play Store readiness. Highest-band evidence should include the signed production APK/AAB, real phone screenshots, listing material, and a release build that installs and runs cleanly.
